# 고등학생 앞에서 진행하는 Mini Redis 시연 매뉴얼

컴퓨터 전공 지식이 없는 고등학생을 대상으로 하는 **약 25분짜리 발표 대본**입니다. 발표자는 이 문서를 옆에 열어 두고 명령을 한 줄씩 입력하면 됩니다. 수식보다 결과를 먼저 보여 주고, 학생에게 다음 결과를 예상하게 한 뒤 원리를 설명합니다.

## 1. 수업 목표와 준비물

수업이 끝나면 학생이 다음 세 문장을 자기 말로 설명할 수 있도록 합니다.

- 이름표를 이용해 내용을 저장하고 다시 찾을 수 있다.
- 공간이 부족하면 가장 오래 사용하지 않은 자료부터 지울 수 있다.
- 유효 시간이 지난 자료는 더 이상 조회되지 않는다.

준비물은 Python 3.8 이상이 설치된 컴퓨터, 프로젝트 폴더, 터미널, 화면을 보여 줄 장치입니다. 실행 중 인터넷 연결이나 외부 패키지는 필요하지 않습니다. 있으면 좋은 준비물은 a, b, c, d라고 적은 종이 카드 네 장입니다.

### 발표 전에 5분 점검

1. 프로젝트 폴더 안에서 터미널을 엽니다. `README.md`와 `mini_redis` 폴더가 보이는 위치여야 합니다.
2. 아래 명령으로 Python과 기존 테스트를 확인합니다.

```powershell
python --version
python -m unittest discover -s tests -v
```

마지막에 `Ran 24 tests`와 `OK`가 나오면 준비된 검사 항목을 통과한 것입니다. `python`을 찾지 못하면 설치된 환경에 따라 `py` 또는 `python3`로 바꿉니다. 수업 중 설치 문제를 해결하지 않도록 반드시 미리 실행해 보세요.

3. 터미널 글자를 뒤쪽 학생도 볼 수 있도록 키우고, 이 문서는 별도 창이나 종이로 준비합니다.
4. 아래 전체 시연을 한 번 연습합니다. 특히 TTL 장면의 기다리는 지점을 확인합니다.
5. 연습한 프로그램은 `quit`으로 종료합니다. 수업은 새 프로그램으로 시작합니다.

### 입력 화면 두 가지를 구분하기

`PS ...>`처럼 보이는 화면은 PowerShell입니다. 이곳에는 `python -m mini_redis`를 입력합니다. `mini-redis>` 화면은 프로그램 안입니다. 이곳에는 `SET`, `GET`, `quit` 등을 입력합니다.

이 문서의 **입력** 블록만 복사합니다. **예상 출력** 블록과 설명 문장, 프롬프트 표시는 입력하지 않습니다. 큰따옴표는 코드 블록에 있는 곧은 모양 `"`을 사용하세요.

### 장면을 바꿀 때 공통 초기화

각 장면은 **빈 저장소에서 시작**합니다. 앞 장면이 끝났으면 `mini-redis>`에서 다음을 입력합니다.

```text
quit
```

PowerShell로 돌아오면 다음으로 새로 실행합니다.

```powershell
python -m mini_redis
```

값뿐 아니라 메모리 한도와 제거 횟수도 초기화됩니다. `CONFIG SET maxmemory 0`만으로는 데이터가 지워지지 않습니다. 장면을 따로 골라 보여 줄 때도 이 방법으로 시작하세요.

## 2. 도입 — 오늘 만들 보관소 (2분)

**말할 내용**

> “이 프로그램은 이름표가 붙은 작은 보관소입니다. 이름표를 말하면 내용을 찾아줍니다. 오늘은 세 가지를 보겠습니다. 저장한 것을 찾기, 공간이 부족할 때 정리하기, 유통기한이 지나면 없애기입니다.”

> “화면에는 영어 명령이 나오지만, 우리가 생각할 것은 이름표와 물건입니다. 이름표를 키, 보관하는 내용을 값이라고 부릅니다.”

PowerShell에서 실행합니다.

```powershell
python -m mini_redis
```

`mini-redis>`가 나타나는 것을 가리키며 “이제 보관소가 명령을 기다리고 있습니다”라고 말합니다.

## 3. 장면 A — 이름표로 저장하고 찾기 (4분)

**시작 상태:** 방금 실행한 빈 저장소. 이 장면에서는 한글 입력 문제를 줄이기 위해 영문 값을 사용합니다.

### A-1. 저장과 조회

**입력**

```text
SET name "Alice Kim"
GET name
```

**예상 출력 — 명령 순서대로**

```text
OK
"Alice Kim"
```

**말할 내용**

> “SET은 넣기, GET은 꺼내 보기입니다. name이 이름표이고 Alice Kim이 내용입니다. 공백이 있는 내용은 큰따옴표로 묶었습니다. 조회한다고 내용이 없어지는 것은 아닙니다.”

### A-2. 존재 확인과 개수

**입력**

```text
EXISTS name
DBSIZE
KEYS
```

**예상 출력**

```text
(integer) 1
(integer) 1
1. "name"
```

**말할 내용**

> “첫 번째 1은 있다는 뜻, 두 번째 1은 저장된 이름표가 하나라는 뜻입니다. integer는 정수라는 표시입니다. KEYS는 이름표 목록을 보여 줍니다.”

키가 여러 개일 때 KEYS의 출력 순서는 보장되지 않습니다. 이 시연은 하나만 두어 순서 차이가 생기지 않게 했습니다.

### A-3. 삭제 결과 예상하기

**학생에게 질문:** “이름표를 지우고 다시 찾으면 어떤 결과가 나올까요?”

두세 명의 답을 듣고 입력합니다.

```text
DEL name
GET name
DBSIZE
```

**예상 출력**

```text
(integer) 1
(nil)
(integer) 0
```

**말할 내용**

> “1은 삭제 성공, nil은 찾는 값이 없다는 뜻입니다. 마지막 0은 저장된 이름표가 이제 없다는 뜻입니다.”

## 4. 장면 B — 공간이 부족하면 무엇을 버릴까? (6분)

**먼저 공통 초기화로 프로그램을 새로 실행합니다.**

### B-1. 세 항목으로 공간 채우기

**말할 내용**

> “이번에는 보관소 크기를 아주 작게 제한하겠습니다. 바이트는 크기를 세는 단위입니다. 여기서는 영문 이름표 한 글자와 숫자 한 글자를 한 쌍으로 저장하므로 항목 하나가 2바이트입니다.”

**입력**

```text
CONFIG SET maxmemory 6
SET a 1
SET b 2
SET c 3
INFO memory
```

**예상 출력**

```text
OK
OK
OK
OK
used_memory:6
maxmemory:6
evicted_keys:0
```

세 숫자를 가리키며 “사용 중인 양 6, 한도 6, 공간 부족으로 지운 개수 0”이라고 읽습니다. 실제 컴퓨터의 전체 메모리 사용량이 아니라, 이 과제에서 정한 키와 값의 바이트 합이라는 점을 짧게 덧붙입니다.

### B-2. 오래된 a를 다시 사용하기

**입력**

```text
GET a
```

**예상 출력**

```text
"1"
```

종이 카드나 손짓으로 다음 순서를 보여 줍니다. **왼쪽이 최근 사용, 오른쪽이 오래 사용하지 않은 항목**입니다.

```text
처음 세 항목을 저장한 뒤: c → b → a
a를 다시 조회한 뒤:      a → c → b
```

**학생에게 질문:** “지금 d를 하나 더 넣으면 8바이트가 됩니다. 어느 항목을 버리는 것이 좋을까요? 처음 넣은 a일까요, 더 오래 안 쓴 b일까요?”

답을 받은 뒤 설명합니다.

> “이 프로그램은 가장 오래 사용하지 않은 것을 버립니다. a는 방금 꺼내 봤으므로 b가 대상입니다. 이 규칙을 LRU라고 합니다.”

**진행 주의:** 이 사이에 확인하려고 `GET b`나 `GET c`를 추가하지 마세요. 조회도 사용 기록을 바꾸므로 예정된 제거 결과가 달라집니다.

### B-3. 예상 확인하기

**입력**

```text
SET d 4
GET b
EXISTS a
EXISTS c
EXISTS d
INFO memory
```

**예상 출력**

```text
OK
(nil)
(integer) 1
(integer) 1
(integer) 1
used_memory:6
maxmemory:6
evicted_keys:1
```

**말할 내용**

> “b가 없어졌고 a, c, d는 남았습니다. 사용량은 다시 한도인 6이 되었고, 지운 개수는 1이 되었습니다. 오래전에 넣었다는 것과 오래 사용하지 않았다는 것은 다릅니다.”

## 5. 장면 C — 유통기한이 있는 값 (5분)

**먼저 공통 초기화로 프로그램을 새로 실행합니다.** 앞 장면의 6바이트 한도가 남아 있으면 이 장면의 값 저장이 실패합니다.

### C-1. 제한이 없는 값에 유효 시간 붙이기

**입력**

```text
SET ticket valid
TTL ticket
```

**예상 출력**

```text
OK
(integer) -1
```

**말할 내용**

> “ticket이라는 입장권을 저장했습니다. 아직 유효 시간을 정하지 않아서 TTL은 -1입니다. 이제 5초 동안만 유효하게 만들겠습니다.”

다음 두 명령은 미리 준비해 빠르게 연속 입력합니다.

```text
EXPIRE ticket 5
TTL ticket
```

**예상 출력**

EXPIRE는 `(integer) 1`입니다. 바로 이어서 실행한 TTL은 보통 `(integer) 4`입니다. 남은 초를 내림하므로 입력 시간에 따라 0~4가 나올 수 있습니다. 5초 이상 지난 뒤 조회하면 -2가 나옵니다. 특정 숫자를 반드시 보여 주려 하지 마세요.

**말할 내용**

> “TTL은 남아 있는 유효 시간입니다. 소수점 아래는 버립니다. 그래서 4.8초가 남아 있으면 4라고 표시합니다. 0도 아직 1초 미만이 남아 있다는 뜻일 수 있습니다.”

### C-2. 만료 확인

**여기서 설명을 잠시 멈추고 6초 이상 기다립니다.** 기다리는 동안 “시간이 지나면 우리가 DEL을 입력해야 할까요?”라고 질문해도 됩니다. 그 뒤 입력합니다.

```text
GET ticket
TTL ticket
DBSIZE
INFO memory
```

**예상 출력**

```text
(nil)
(integer) -2
(integer) 0
used_memory:0
maxmemory:0
evicted_keys:0
```

**말할 내용**

> “이제 입장권이 없습니다. TTL의 -2는 키가 없다는 뜻입니다. 공간 부족으로 버린 것이 아니라 시간이 지나 만료된 것이어서 evicted_keys는 0입니다. maxmemory의 0은 한도 없음이라는 뜻입니다.”

발표자 참고: 입력을 기다리는 동안 별도 삭제 작업이 도는 구현은 아닙니다. 다음 명령이 시작할 때 만료된 항목을 정리합니다. 학생이 물으면 “시간이 지난 값을 다시 요청하면, 먼저 기한을 확인하고 지워서 돌려주지 않습니다”라고 설명하세요.

### C-3. 선택 시연 — 내용을 바꾸면 기한은?

시간이 남으면 같은 프로그램에서 입력합니다.

```text
SET note first
EXPIRE note 60
SET note second
TTL note
```

**예상 출력**

```text
OK
(integer) 1
OK
(integer) -1
```

> “이 프로그램에서는 SET으로 새 내용을 저장하면 이전 유효 시간을 지웁니다. 새 내용에도 시간이 필요하면 EXPIRE를 다시 입력합니다.”

## 6. 장면 D — 잘못된 입력도 처리하기 (3분)

**먼저 공통 초기화로 프로그램을 새로 실행합니다.**

### D-1. 입력 실수

**입력**

```text
HELLO
GET
CONFIG SET maxmemory abc
```

**예상 출력**

```text
(error) ERR unknown command 'HELLO'
(error) ERR wrong number of arguments for 'GET' command

```

> “첫 번째는 모르는 명령, 두 번째는 무엇을 찾을지 빠진 명령, 세 번째는 숫자가 필요한 자리에 글자를 넣은 경우입니다. 오류를 설명하고 다음 입력을 기다리는 것도 프로그램의 기능입니다.”

### D-2. 너무 큰 값으로 바꾸려 하면?

**입력**

```text
CONFIG SET maxmemory 4
SET a 1
SET a 12345
GET a
INFO memory
```

**예상 출력**

```text
OK
OK
(error) OOM command not allowed when used_memory > 'maxmemory'
"1"
used_memory:2
maxmemory:4
evicted_keys:0
```

**말할 내용**

> “새 이름표와 내용의 합은 6바이트라서 한도 4에 들어가지 않습니다. 그래서 저장을 거절하고 원래 값 1을 남겼습니다. OOM은 공간이 부족하다는 뜻입니다.”

오류 문구에 `used_memory > 'maxmemory'`가 들어 있어도 현재 저장된 양이 이미 4를 넘었다는 뜻으로 설명하지 마세요. 이 장면에서는 새 항목이 한도보다 커서 거절되었으며 기존 사용량은 2입니다.

## 7. 마무리 — 안쪽에서는 어떻게 찾을까? (2분)

코드 전체를 화면에 펼치기보다 다음 세 설명을 전달합니다.

> “첫째, 해시맵은 이름표를 계산해서 보관할 칸을 정합니다. 처음부터 모든 물건을 뒤지는 일을 줄입니다. 같은 칸에 여러 이름이 들어가면 실제 이름을 비교합니다.”

> “둘째, 이중 연결 리스트는 앞뒤가 연결된 줄입니다. 사용한 물건을 앞으로 옮기고, 공간이 부족하면 맨 뒤를 지웁니다. 해시맵이 물건을 찾아주고 물건이 자기 줄 위치를 기억해서 빠르게 옮길 수 있습니다.”

> “셋째, 최소 힙은 가장 빨리 만료될 것을 맨 위에 둡니다. 유통기한이 가장 급한 것부터 확인할 수 있습니다.”

**마지막 확인 질문**

1. “SET과 GET은 각각 무엇을 하나요?” → 저장과 조회.
2. “방금 조회한 a와 오래 안 쓴 b 중 공간 부족 때 누구를 지웠나요?” → b.
3. “TTL -1과 -2는 어떻게 다른가요?” → 기한 없음과 키 없음.

> “이번 프로그램은 이름 검색, 최근 사용 순서, 만료 순서에 각각 맞는 자료구조를 조합했습니다. 오늘은 그 동작을 본 것이고, 실제 속도를 재는 실험을 한 것은 아닙니다.”

마지막으로 `quit`을 입력합니다. “오늘 저장한 내용은 프로그램을 끄면 사라집니다”라고 안내합니다. 복습용으로 [학습 자료](LEARNING_GUIDE.md)와 [실습·해설](EXERCISES.md)을 공유합니다.

## 8. 현장에서 막혔을 때

### `No module named mini_redis`가 나온다

프로젝트 밖에서 실행했을 가능성이 있습니다. PowerShell에서 다음 위치로 이동한 뒤 다시 실행합니다. 다른 컴퓨터에서는 실제 내려받은 폴더 경로로 바꾸세요.

```powershell
cd "C:\Users\Jingeol Lee\Desktop\B3-1"
python -m mini_redis
```

### SET부터 OOM이 나온다

이전 장면의 메모리 한도가 남았는지 확인합니다. 공통 초기화로 다시 실행하고 해당 장면 처음부터 진행합니다. 실수한 상태에서 일부 명령만 반복하는 것보다 결과를 맞추기 쉽습니다.

### LRU에서 예상과 다른 키가 지워졌다

중간에 GET으로 다른 키를 확인했다면 사용 순서가 달라집니다. “조회 자체가 사용 기록을 바꿨습니다”라고 설명하고 장면 B를 새로 시작합니다. 데이터 존재만 확인하려면 EXISTS를 사용합니다.

### TTL이 예상 숫자보다 작거나 바로 -2가 나온다

설명하는 동안 시간이 지난 것입니다. 프로그램 오류로 단정하지 마세요. 다시 `SET ticket valid`, `EXPIRE ticket 5`, `TTL ticket` 순서로 빠르게 입력하고 6초 이상 기다린 뒤 GET으로 만료를 확인합니다. 이미 없는 키에 EXPIRE만 호출하면 0이 나오므로 SET부터 다시 해야 합니다.

### 따옴표 오류 또는 인자 개수 오류가 나온다

코드 블록에서 명령만 다시 복사합니다. `mini-redis>`나 설명을 함께 넣지 않았는지, 공백이 있는 값을 `"Alice Kim"`처럼 감쌌는지 확인합니다. 오류 뒤에도 프로그램은 다음 입력을 받습니다.

### 프로그램이 끝났거나 입력 화면을 혼동했다

PowerShell의 `PS ...>`가 보이면 `python -m mini_redis`로 다시 시작합니다. 새 실행은 빈 상태이므로 현재 장면의 첫 명령부터 진행합니다. `mini-redis>` 안에서는 `python` 명령을 입력하지 않습니다.

### 시간이 10분밖에 남지 않았다

도입 1분, 장면 A의 저장·조회·삭제 2분, 장면 B 4분, 장면 C의 기본 만료 시연 2분, 마무리 1분으로 줄입니다. 장면 D와 TTL 덮어쓰기 선택 시연은 생략합니다. 장면 사이 초기화는 생략하지 않습니다.

### 현장에서 실행 자체가 불가능하다

이 문서의 예상 출력을 화면에 띄우고 종이 카드로 LRU 순서를 재현합니다. 이 경우 “지금은 실제 실행 대신 준비된 예시로 원리를 설명하겠습니다”라고 밝힙니다. 학생이 결과를 먼저 예상하게 하는 질문은 그대로 진행할 수 있습니다.
