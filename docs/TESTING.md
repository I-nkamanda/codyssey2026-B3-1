# 테스트 실행과 검증 범위

## 실행

프로젝트 최상위 폴더에서 다음 명령을 실행합니다. 외부 설치는 필요하지 않습니다.

```powershell
python -m unittest discover -s tests -v
```

성공하면 마지막에 `Ran 24 tests`와 `OK`가 나옵니다. 2026-09-06 로컬 Windows, Python 3.14.7에서 24개 테스트를 모두 통과했습니다. 실제 실행 시간은 컴퓨터마다 다릅니다.

## 자료구조 테스트

`tests/test_structures.py`는 동적 배열의 확장·중간 삭제·잘못된 인덱스, 리스트의 앞뒤 삽입·삭제·노드 이동·소속 확인, 실제 해시 충돌·덮어쓰기·0.75 경계 확장·한글 키, 힙의 정렬 규칙·동일 시각·같은 키 교체를 확인합니다.

힙 무작위 테스트는 시드 42로 3,000회 연산합니다. 고정 길이 기준 배열에 기대값을 따로 보관하고 최소값을 비교합니다. 각 연산 뒤 위치 인덱스와 부모/자식 순서도 확인합니다. 기대값 계산용 `min`은 테스트 코드에서만 사용하며 힙 구현을 대신하지 않습니다.

## 저장소 테스트

`tests/test_store.py`는 기본 CRUD, 빈 키와 값, UTF-8 크기, 과제의 22바이트 예시, GET과 SET의 LRU 갱신, 여러 키 제거, OOM 기존 값 보존, 한도 축소, 무제한 설정, 정확한 만료 경계, TTL 갱신·초기화·즉시 만료, 삭제 후 재생성, 전체 조회의 만료 정리를 확인합니다.

시드 19로 2,000회 저장·조회·삭제·만료·시간 경과·한도 변경을 섞으며 자료구조 간 불변식을 검사합니다. 이 검사는 모든 명령 출력의 독립적인 정답 모델을 대체하지는 않습니다. 출력과 정책의 구체적 결과는 별도의 예제 테스트로 확인합니다.

TTL 테스트는 `FakeClock`으로 시간을 움직입니다. 실제 시간을 기다리지 않아도 정확한 만료 시점을 재현할 수 있습니다.

## CLI 테스트

`tests/test_cli.py`는 10개 필수 명령과 종료, 빈 입력, 대소문자, 공백·빈 문자열·한글·따옴표, 알 수 없는 명령, 인자 개수 오류, 정수 범위·형식 오류, OOM을 확인합니다. 오류 이후 정상 명령을 계속 실행할 수 있는지도 검사합니다.

별도 Python 프로세스로 `python -m mini_redis`를 실행하고 실제 프롬프트, 입출력, quit 및 EOF 종료를 확인합니다.

## GitHub 자동 실행

`.github/workflows/tests.yml`은 push와 pull request 및 수동 실행 시 Python 3.8, 3.12, 3.14에서 같은 테스트를 실행하도록 구성되어 있습니다. 로컬에서 실제 검증한 버전은 3.14.7입니다. 다른 버전의 원격 통과 여부는 저장소 업로드 후 Actions 화면에서 확인하세요.

## 검사하지 않은 범위

실제 Redis 서버와의 호환성 비교, 네트워크, 동시성, 영속성, 장시간 서비스 운영, 성능 벤치마크는 이 과제의 구현 및 검증 범위에 포함되지 않습니다. Big-O 설명은 구현 구조에 대한 분석이며 벤치마크 측정 결과가 아닙니다.
