# 요구사항과 구현 설명

## 범위

[과제 원문](../b3-1-mission.md)의 필수 기능 전체를 구현했습니다. 선택 기능은 동적 배열 구현과 [스택·큐·덱 설명](STACK_QUEUE_DEQUE.md)입니다. 이진 트리 순회, BST, Pub/Sub는 포함하지 않습니다.

## 요구사항을 찾을 위치

- 이중 연결 리스트: `mini_redis/linked_list.py`의 `Node`, `DoublyLinkedList`. 요구된 6개 메서드와 prev/next/data를 제공합니다.
- 해시맵: `mini_redis/hash_map.py`의 `HashMap`. put/get/remove/contains/keys/size, 직접 작성한 해시 계산, 연결 리스트 체이닝, 0.75 초과 시 두 배 확장을 구현했습니다.
- 최소 힙: `mini_redis/min_heap.py`의 `MinHeap`. push/pop/peek/size와 `_heapify_up`, `_heapify_down`을 구현했습니다. 키별 삭제를 위한 `remove`도 추가했습니다.
- 기본 6개 명령: `mini_redis/cli.py`의 `_run`과 `mini_redis/store.py`의 set/get/delete/exists/dbsize/keys.
- 메모리 명령: configure_maxmemory, memory_info, `_evict`.
- TTL 명령: expire, ttl, `_purge_expired`.
- 입력·종료·오류: `CommandProcessor.execute`, `parse_integer`, `main`.
- 동적 배열: `mini_redis/dynamic_array.py`. append/get/set/remove, 용량 두 배 확장을 구현해 힙 저장소에 사용합니다.

## 데이터의 관계

`MiniRedis.data`는 키 → Entry를 저장합니다. Entry에는 키, 값, UTF-8 크기, 만료 시각, LRU 노드가 있습니다. `MiniRedis.lru`의 각 노드 data는 키입니다. `MiniRedis.expirations`는 만료 시간이 있는 키만 담습니다.

힙의 `_positions`도 직접 만든 해시맵이며 키 → 힙 배열 인덱스를 저장합니다. 버킷과 동적 배열의 실제 저장 공간은 고정 길이 list입니다. 튜플은 키/값 등의 묶음을 표현하는 데 사용합니다. 내장 list/dict로 키 검색을 대체하지 않습니다. CLI의 토큰 목록은 표준 파서 결과이며 저장소 역할을 하지 않습니다.

표준 라이브러리 `shlex`, `re`, `json`, `time`은 각각 입력 분리, 정수 형식 검사, 출력 문자열 이스케이프, 시계용입니다. `json`은 문자열을 따옴표로 표현하는 용도로만 사용합니다. 저장소 구현에서 dict/set/collections/heapq를 사용하지 않습니다.

## SET의 순서

1. 만료된 키를 정리합니다.
2. 새 키+값의 UTF-8 크기를 계산합니다.
3. 한 항목 자체가 한도를 초과하면 오류를 냅니다.
4. 같은 키가 있으면 공통 삭제 절차로 기존 데이터·TTL·LRU·사용량을 정리합니다.
5. 새 Entry와 LRU 맨 앞 노드를 저장하고 사용량을 늘립니다.
6. 한도를 넘는 동안 LRU 뒤에서부터 삭제하고 evicted_keys를 증가시킵니다.

새 항목은 가장 최근 사용한 위치에 있고, 단독 크기 검사를 통과했으므로 필요한 이전 항목을 제거하면 새 항목을 남긴 채 한도를 만족합니다.

## TTL 전략

지연 삭제 방식 대신 **키의 힙 위치를 추적해 즉시 원소를 제거하는 방식**을 선택했습니다. EXPIRE 재설정은 기존 힙 원소를 제거하고 새 `(expire_at, key)`를 넣습니다. DEL, 덮어쓰기, LRU 제거에서도 힙 원소를 실제로 삭제합니다. 키 하나당 만료 원소는 최대 하나입니다.

`_purge_expired`는 현재 시각을 한 번 읽은 뒤 힙 맨 위가 만료되었으면 삭제를 반복합니다. 힙은 부모가 자식보다 작거나 같으므로 맨 위가 미래라면 아래 원소도 아직 만료되지 않았습니다.

`ttl`은 같은 시각을 만료 정리와 남은 시간 계산에 사용합니다. 유효한 남은 시간의 소수점을 버리므로 0.5초 남았을 때 0을 반환합니다. 정확히 만료 시각이면 삭제하고 -2입니다.

입력 대기 중 삭제 작업은 실행하지 않습니다. 다음 유효한 저장소 연산이 시작할 때 만료를 정리합니다. DBSIZE, KEYS, INFO에도 적용하므로 그 명령의 결과에 지난 만료 데이터가 남지 않습니다. 잘못된 문법이나 종료 명령은 저장소 연산을 수행하지 않습니다.

## 모호한 부분에 대한 결정

- CONFIG로 한도를 낮추면 즉시 제거합니다. 예를 들어 4바이트가 저장되어 있을 때 한도를 2로 낮추면 그 명령 안에서 정리합니다.
- EXPIRE의 0과 음수 초는 즉시 삭제하고 키가 있었으면 1을 반환합니다.
- OOM 덮어쓰기는 유효한 기존 값·TTL·LRU 순서를 보존합니다. 정상적인 만료 정리는 OOM 판단보다 먼저 수행합니다.
- KEYS는 순서를 보장하지 않으며 1부터 번호를 붙입니다. 빈 경우 `(empty array)`입니다.
- 정수 입력은 선택적 + 또는 - 부호와 ASCII 숫자만 허용합니다. 64비트 범위 밖, 소수, 밑줄 표기 등은 정수 오류입니다.
- 공개 사용 진입점은 CLI이며 명령 문법 검증은 CLI가 담당합니다. 내부 Python 메서드는 파싱된 문자열·정수 입력을 전제로 합니다.

## 시간 복잡도를 설명할 때의 주의

연결 리스트의 노드 삽입·삭제·이동은 O(1)입니다. 해시맵 조회·갱신·삭제는 적절한 분산을 가정하면 평균 O(1)이지만, 키를 바이트로 읽는 O(키 길이) 비용과 충돌 비용이 있습니다. 확장 시에는 기존 엔트리를 다시 배치합니다.

힙의 최소 원소 확인은 O(1)입니다. 위치 해시맵 연산을 평균 O(1)로 보면 힙 추가·삭제는 통상 O(log t)입니다. t는 TTL이 있는 키 개수입니다. 동적 배열이나 위치 해시맵 확장이 발생하는 한 번의 연산은 추가 비용이 있습니다. 배열 append 자체는 분할 상환 O(1)입니다.

GET 성공 시 LRU 이동은 O(1)이지만 **명령 전체**는 앞서 만료된 키를 정리하는 만큼 더 오래 걸릴 수 있습니다. SET도 여러 키의 LRU 제거와 TTL 삭제가 발생할 수 있으므로 전체를 무조건 O(1)이라고 설명하지 않습니다.

KEYS는 버킷과 모든 키를 순회합니다. 해시맵은 축소하지 않으므로 자료를 많이 넣었다가 지운 뒤에도 큰 버킷 배열이 남습니다. 따라서 정확히는 현재 버킷 수와 키 수에 비례합니다. TTL 힙 배열과 위치 해시맵도 용량을 축소하지 않습니다. 이 공간은 과제의 used_memory에서 제외됩니다.

## 유지해야 하는 불변식

- 데이터 키 개수 = LRU 노드 개수.
- used_memory = 모든 Entry.byte_size의 합.
- 각 Entry의 lru_node는 같은 키를 가리키며 현재 LRU 리스트 소속입니다.
- 만료 시각이 있는 키 개수 = 힙 원소 개수 = 위치 인덱스 항목 수.
- 힙 각 부모는 자식보다 작거나 같습니다.
- 위치 인덱스는 원소의 실제 배열 위치와 일치합니다.
- 명령이 정상 완료된 뒤 한도가 양수이면 used_memory ≤ maxmemory입니다.

이 규칙들은 고정 예제뿐 아니라 무작위 연산 뒤에도 자동 테스트로 검사합니다. 실행 방법과 범위는 [TESTING.md](TESTING.md)를 참고하세요.
